# One 10-second short in ultrafast, Remotion, HyperFrames and Shotstack: tokens, facts, method

2026-11-22. Render timings are not reported here; they come from the shared benchmark.

## The job

The same short in all four tools:
- 10 s vertical, 1080×1920, 30 fps, H.264 MP4;
- NASA footage as the background (`iss_earth_limb.mp4`, public domain, the same file in every project);
- a title that animates in, and three lines of detail;
- captions timed to each word: 15 given words from 3.0 to 9.6 s;
- a colour grade (exposure −0.2, contrast up, saturation down) and film grain.

The grain is matched across the three rendered tools: each adds a noise std of about 2.45/255 in a flat 360×360 crop at 4.8 s.

**Versions:**
- ultrafast 0.1.1 (`bin/ultrafast`, a copy of `~/ultrafast/target/release/ultrafast`)
- Remotion 4.0.545 (latest on npm), with its 13 agent skills
- HyperFrames 0.9.79 (latest on npm), with its skills
- Shotstack Edit API, written and validated only; rendering needs an account

| Licence | Apache-2.0 or MIT | Apache-2.0 | source-available; a company licence is needed at 4+ people | proprietary API |

So ultrafast's document is 19% fewer tokens than HyperFrames and 27% fewer than Remotion and Shotstack.

The site's `TOKENS` estimates do not hold up: 1,100 / 4,400 / 5,500 tokens, and "a fifth of the tokens" or "up to 80% fewer". Both competitors now do the grade, the grain and word captions with built-ins:
- **Remotion:** `@remotion/effects` (`colorCorrection()`, `noise()`) and a caption Element that its CLI installs.
- **HyperFrames:** the `media-treatment` command, which takes `adjust` and `grain` settings.

Most of their tokens therefore describe the video, not plumbing.

### What was counted

- **"Edits" (the headline measure)** is everything the agent types after each tool's own scaffold step: `ultrafast new vertical`, `npx create-video --yes --blank --skills`, or `npx hyperframes init --example blank --resolution portrait`. It includes:
  - new files in full;
  - the added or changed lines of scaffold files, taken from the unified-diff `+` lines against the scaffold commit in each project's git history;
  - commands that carry content.
- **"Whole"** is the full text of every file the agent creates or edits.
- **Excluded:**
  - lockfiles and `node_modules`;
  - `package.json` changes made by CLIs;
  - scaffold files left untouched;
  - render commands;
  - code generated by the tools.

The script is `tokens.py` and its output is `tokens.json`.

## Method

Each version follows its tool's own docs and agent skills, as a competent user would. Nothing was written to favour any tool.

- **ultrafast:** one document using `video` (fit cover), `adjust`, `grain`, `text` with keyframes, and `captions` with `stroke_outline`, as in the agent guide. Checked with `ultrafast check`.
- **Remotion:** written as its skills direct:
  - the scaffold's `Composition.tsx`, with `<Video>` from `@remotion/media`;
  - grade and grain as `@remotion/effects` on the video;
  - `Interactive.Div` with inline `interpolate()` for the title and lines;
  - `@remotion/google-fonts/Inter`;
  - captions inline on the Word Highlight Captions Element.

  Its effects need WebGL in renders. The docs suggest `angle`, but here that gives no WebGL2 context, so the config uses `angle-egl` (documented for Linux). Typecheck is clean.
- **HyperFrames:** the blank scaffold's `index.html`:
  - a muted `<video class="clip">`;
  - a GSAP timeline for the title and lines;
  - word-timed caption groups as `captions.md` describes;
  - grade and grain through `media-treatment`, as its contract requires (never CSS filters).

  `hyperframes check`: ok, warnings only. One says the root should hold sub-compositions; five say captions sit near TikTok's right-edge UI.
- **Shotstack:** written from the current API schema (`api.edit.json`) and the rich-caption guide:
  - a `video` clip with `filters` (grade, contrast, saturation);
  - `rich-text` clips with `slideIn` animations;
  - a `rich-caption` clip in karaoke style from an SRT with one cue per word;
  - a grain video overlaid at 12% opacity.

  `shotstack validate` (`@shotstack/cli` 0.17.0, offline) reports one error: it rejects clip `filters`, although the current API reference and `@shotstack/schemas` 1.27.0 both define it (`shotstack/validate.txt`). Font families use the font file's name, as the validator asks.

**Checking that the three versions match:** ultrafast, Remotion and HyperFrames were rendered. `contact_sheet.png` shows 4 moments × 3 tools, and the MP4s are in `out/`.

| What | Status |

| HyperFrames grade | renders a little brighter |

## Shotstack facts (official pages only, checked 2026-11-22; also in `shotstack/facts.json`)

- **Where it renders:** hosted only, on Shotstack's cloud. No self-hosted or on-premise option is offered on any official page or repository. Their own words: "a fully managed API … no infrastructure to maintain". https://shotstack.io/vs/remotion-alternatives/
- **Engine:**
  - Closed source. They describe CPU-optimised processing that splits a render across servers (https://shotstack.io/learn/rendering-speeds-benchmark/).
  - GPU is not mentioned. The Edit schema offers an `a1` "accelerated instance" (https://shotstack.io/docs/api/api.edit.json).
- **Licence:**
  - The render engine and API are proprietary.
  - The SDKs and demos are MIT.
  - The Studio editor SDK is PolyForm Shield 1.0.0: source-available, and it may not be used to compete with Shotstack. https://github.com/shotstack/shotstack-studio-sdk/blob/main/LICENSE
- **Pricing per rendered minute** (https://shotstack.io/pricing/): minutes are counted by the second, rounded down, and you start free with 10 credits.

  | Plan | Price | Minutes | Per minute |
  |---|---|---|---|
  | Pay as you go | $10 | 50 | 20¢ |
  | Starter | $39/mo | 250 | 15.6¢ |
  | Pro | $99/mo | 750 | 13.2¢ |
  | Scale | $199/mo | 2,000 | 10¢ |
  | Volume | $499/mo | 10,000 | 5¢ |

  4K needs Pro or above. Sandbox renders are watermarked, limited to 10 minutes and need at least one credit. https://shotstack.io/docs/guide/architecting-an-application/limitations/
- **Published render speed:**
  - "Rendering takes approximately 20 seconds per minute of video. Additional effects, filters, or transitions increase render time." (limitations page)
  - 2024 benchmark: a 60 s 1080p video in 22.8 s, "3x real time". The machine is not stated, and upload, queue and download are not included. https://shotstack.io/learn/rendering-speeds-benchmark/
  - None of this was measured here.
- **Agent tooling:**
  - Hosted MCP server at `https://mcp.shotstack.io/` (Streamable HTTP, OAuth or API key), with setup for Claude, ChatGPT, Cursor, VS Code, Codex and Gemini CLI. https://shotstack.io/docs/guide/agents/mcp-server/
  - A CLI (`@shotstack/cli`) with an agent skill, llms.txt, and n8n, Make and Zapier integrations.
- **Output formats:** mp4, gif, mp3, jpg, png and bmp (no webm or mov). Custom sizes go up to 3840 px a side, so 2160×3840 vertical is allowed, at 12–60 fps. https://shotstack.io/docs/api/#tocs_output
- **What this short needs there:**
  - Footage, fonts and captions must be at public URLs.
  - Word timings come from a subtitle file or from transcription; they cannot be inlined.
  - There is no built-in grain (the overlay clip is a workaround, not a documented feature).
  - (https://shotstack.io/docs/guide/architecting-an-application/rich-captions/)

## Caveats

1. **Token counts depend on authoring style.** These are one competent version of each, not a minimum.
   - Remotion follows its skills (Studio-editable `Interactive.Div` with inline `interpolate()`). A terser, non-editable style would be smaller.
   - HyperFrames was kept to one file, like its blank scaffold. Its skill recommends a sub-composition per scene and a captions host, which would add tokens.
   - Its registry caption components must be copied into the composition (several thousand tokens), so the hand-written captions favour HyperFrames.
2. **The tokenizer is OpenAI's `o200k_base`, not Claude's.** The ratios should hold roughly; the absolute counts will differ.
3. **Shotstack is unverified.** Its JSON was never rendered, so whether its frames match is unknown, and its official validator rejects `filters`.
4. **Side effect of `hyperframes init`.** By default it installs skills globally into `~/.claude/skills` and `~/.agents/skills`. That was reverted here, and a copy is kept in `hyperframes-skills-ref/`.
